# Git Workflow Rules for BloomUP Team

##  **Daily Workflow - ALWAYS Follow This Order:**

### **1. START OF DAY - Pull Latest Code**
```bash
# Switch to your working branch
git checkout your-branch-name

# Push your current work to your branch (save your progress)
git add .
git commit -m "WIP: Your current work description"
git push origin your-branch-name

# Switch to development branch
git checkout development

# Pull latest changes from development
git pull origin development

# Switch back to your branch
git checkout your-branch-name

# Merge development into your branch
git merge development
```

### **2. IF CONFLICTS ARISE - Resolve Them:**
```bash
# Check which files have conflicts
git status

# Open conflicted files and resolve manually
# Look for <<<<<<< HEAD, =======, >>>>>>> development markers
# Edit files to keep the correct code

# After resolving conflicts:
git add .
git commit -m "Resolve merge conflicts with development"
git push origin your-branch-name
```

### **3. END OF DAY - Push Your Work:**
```bash
# Make sure you're on your branch
git checkout your-branch-name

# Add all changes
git add .

# Commit with descriptive message
git commit -m "Feature: Add vaccination date calculation"

# Push to your branch
git push origin your-branch-name
```

## 📋 **Branch Management:**

### **Your Working Branch:**
- Always work on YOUR branch (e.g., `vaibhav-developer`, `john-feature`, `sarah-bugfix`)
- Never work directly on `development` or `main`
- Name your branch: `your-name-feature` or `your-name-bugfix`

### **Development Branch:**
- `development` is the main integration branch
- All features merge into `development` first
- Only merge to `development` when your feature is complete and tested

### **Main Branch:**
- `main` is for production-ready code only
- Only merge from `development` to `main` for releases

## ⚠️ **Conflict Resolution Rules:**

1. **NEVER** force push (`git push --force`) unless absolutely necessary
2. **ALWAYS** resolve conflicts manually - don't use auto-merge tools
3. **COMMUNICATE** with team if conflicts are complex
4. **TEST** your code after resolving conflicts
5. **COMMIT** conflict resolution with clear message

## 🔄 **Complete Workflow Example:**

```bash
# Morning routine
git checkout vaibhav-developer
git add .
git commit -m "WIP: Vaccination dashboard updates"
git push origin vaibhav-developer

git checkout development
git pull origin development
git checkout vaibhav-developer
git merge development

# If conflicts:
# Resolve conflicts manually
git add .
git commit -m "Resolve conflicts with development"
git push origin vaibhav-developer

# Continue working...
# Make changes to files
git add .
git commit -m "Feature: Add vaccination date calculation"
git push origin vaibhav-developer

# End of day
git add .
git commit -m "Complete: Vaccination dashboard with dates"
git push origin vaibhav-developer
```

## 📝 **Commit Message Guidelines:**

- **Feature:** `Feature: Add vaccination date calculation`
- **Bugfix:** `Fix: Resolve dashboard update issue`
- **Refactor:** `Refactor: Clean up vaccination controller`
- **WIP:** `WIP: Working on calendar integration`
- **Complete:** `Complete: Vaccination scheduling feature`

## 🚨 **Emergency Situations:**

If you accidentally commit to `development`:
```bash
# Create a new branch from your commit
git checkout development
git checkout -b your-name-emergency-fix
git push origin your-name-emergency-fix

# Reset development to previous commit
git checkout development
git reset --hard HEAD~1
git push origin development --force-with-lease
```

## 📞 **Team Communication:**

- **Slack/Teams:** Notify team about major conflicts
- **Code Review:** Always request review before merging to development
